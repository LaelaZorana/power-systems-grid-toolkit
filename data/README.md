# Data

## Cases, data/cases/

Each case is one JSON file with the keys `name`, `base_mva`, `source`, `buses`,
`gens` and `branches`. The tables are lists of dicts using the same keys the
solvers expect, so nothing gets renamed on the way in and you can read a case
file and a solver call side by side.

Bus fields: `bus` numbered 1 to n, `type` with 3 slack, 2 PV and 1 PQ, `Pd`
and `Qd` load in MW and MVAr, `Gs` and `Bs` shunt in MW and MVAr at 1.0 pu
voltage, `Vm` and `Va` the initial voltage magnitude in pu and angle in
degrees.

Gen fields: `bus`, `Pg` and `Qg` scheduled output in MW and MVAr, `Qmax` and
`Qmin` reactive limits in MVAr, `Vset` the voltage setpoint in pu, `Pmax` and
`Pmin` in MW. Generators that the source data reports out of service aren't
included at all, so a gen row you see here is a gen the solver will use.

Branch fields: `from`, `to`, `r`, `x` and `b` in pu on the system base, `tap`
off-nominal turns ratio on the from side with 0 meaning nominal, `shift`
phase shift in degrees, `status` with 0 meaning out of service.

Sources and validation. All three cases are the classic IEEE test systems
from the University of Washington power systems test case archive, and they
were transcribed mechanically from the MATPOWER distribution files `case14.m`,
`case_ieee30.m` and `case57.m` rather than by hand, because one mistyped
reactance in a 57-bus case will still converge and still look plausible.
Newton-Raphson results on the transcribed files, flat Q limits not enforced:

| Case | Buses | NR iterations | Losses | Slack P | Known ballpark |
|---|---|---|---|---|---|
| ieee14.json | 14 | 3 | 13.39 MW | 232.4 MW | 13.39 MW |
| ieee30.json | 30 | 3 | 17.56 MW | 261.0 MW | 17.5 to 17.6 MW |
| ieee57.json | 57 | 4 | 27.86 MW | 478.7 MW | 27.9 MW |

`tests/test_cases.py` checks convergence and these loss values on every run.

Load a case with

```python
from psa.data import load_case
case = load_case("ieee30")
```

## Profiles, data/profiles/

None of this is measured data, and it would be a mistake to use it as if it
were. All three CSV files are synthetic, generated by `make_profiles.py` in
this directory with the fixed seed 20260815, and each file says so in its own
comment header so a stray copy can't lose that context. Lines starting with
`#` are comments and the first plain line is the CSV header.

- `load_8760.csv`, columns `hour` and `load_mw`. Hourly load for a small
  summer peaking utility over one year, running from a 50 MW minimum up to a
  150.4 MW peak for an annual energy of 778 GWh. The shape is a seasonal
  cosine peaking near day 200 crossed with a double humped diurnal curve where
  the evening peak dominates, pulled down to 90 percent at weekends, with 3
  percent Gaussian noise on top.
- `pv_cf_8760.csv`, columns `hour` and `cf`. Hourly PV capacity factor from a
  clear sky solar elevation model at latitude 40 N, with autocorrelated daily
  cloud attenuation so that cloudy days come in runs rather than scattered at
  random, plus hourly flicker. Annual capacity factor 0.152.
- `wind_cf_8760.csv`, columns `hour`, `wind_speed_ms` and `cf`. Hourly wind
  speeds drawn from a Weibull distribution with shape 2.1 and scale 8.0 m/s
  through an autocorrelated Gaussian driver, then converted with the toolkit
  power curve. Annual capacity factor 0.310.

Load a column with

```python
from psa.data import load_profile
load = load_profile("load_8760", "load_mw")
```
